Shield ドキュメント/Get started

英語のガイド

Your first Shield project

Set up a project policy, connect Claude Code or Codex, and inspect an agent request. For an overview of the concepts, read What is Shield?.

Before you begin

You need the shield command on your path. The terminal steps below require an interactive terminal; a connected agent uses the host’s confirmation form. If you are building from the Canonic checkout, the local installer is:

cd packages/shield
cargo xtask install

The installer puts shield in ~/.local/bin; add that directory to your PATH. See development for build details. macOS and AMD64 Windows have native verification; ARM64 Windows is implemented but unverified. On Windows, follow the portable installation instructions and read the command coverage. On GNU/Linux, use the Linux build and portable installation instructions. The Linux binary’s glibc requirement is recorded with its build; broader host coverage and ARM64 behavior are accepted without extra tests for this stage.

Open a terminal in your project. Default setup downloads a signed baseline pack from Shield’s main registry, so you need network access.

1. Initialize the project

If Shield’s MCP tools are already connected to your agent, ask it to set up Shield. In a fresh project it can use init, show you the setup review and continue configuration on the same connection after you accept. For a combined Hub and Shield setup, the agent initializes Hub, registers the existing project, configures Shield through Hub and publishes its hooks. Reload the affected agent to load new registrations. See agent setup.

From the project directory, run:

shield init

Shield asks you to choose a profile for the baseline, its default pack of permission rules. Recommended is preselected. A profile selects the pack’s decisions; it does not change your agent’s sandbox.

At the agent selection, use Space to mark the agents to configure, then Enter to continue. Agents whose commands are on your path are preselected. Enter with none marked skips agent setup; you can add it later.

Review the packs, agent settings, and Shield binary path, then confirm. Shield saves the active policy and creates .shield/ for policy files and private runtime state in .shield/state/. To keep the policy files in .config/shield/ or another file instead, see where the configuration lives. Cancel leaves the project unchanged; a failed baseline download or verification leaves a new project unenrolled.

For a first setup with a different baseline profile, use shield init --profile strict. To start without adding the default baseline, use shield init --no-baseline. An empty policy returns Ask for unmatched requests.

2. Load the agent integration

If you selected an agent during initialization, its registrations are already installed. To add one later, choose the command for your agent:

shield mcp setup --agent claude
shield mcp setup --agent codex

Each command installs hooks and MCP tools for that agent after review, keeping any other selected agent registered.

Restart the agent after setup. Trust the project, enable hooks, and approve the MCP connection as the host requires. In Codex, also review the hook definitions through /hooks.

Codex: new setups let valid Ask requests proceed by default, even with the Strict profile. Saved choices are preserved; Deny and protection failures still block. Check this fallback in the review. See Ask handling.

Hooks check supported tool requests. MCP lets the agent inspect policy, read guides, and propose changes. Check that both load in the restarted agent.

3. Inspect the result

Run these from the same project:

shield status
shield doctor

Check that status names the right project and lists your packs and agents. doctor adds diagnostic checks and recovery commands. Resolve any reported repair before continuing. Both report installation state; live interception remains unverified.

To inspect the rules themselves, use:

shield rule list --json

JSON output includes full identifiers and structured details.

4. Inspect an agent request

Continue your ordinary work in the restarted agent. When Shield records a request, you can inspect it in the terminal:

shield history list

Copy an entry ID from the list and use it in place of ENTRY:

shield history show ENTRY

Find a command the agent submitted. The detail view shows its decision, matching rules, and any reported completion. A decision alone does not show that execution finished. If history is empty, follow integration troubleshooting.

Where to go next

Read policy decisions to understand the result of a request. Then find a permission pack or write a custom rule for your project’s needs. Agents can use Shield’s MCP tools to inspect policy and prepare changes for your review.
