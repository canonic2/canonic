Canonic Shield

Autorisations de projet pour les agents de développement.

Shield vérifie les commandes, les lectures de fichiers et les requêtes web de Claude Code et de Codex selon les règles de votre projet. Chaque requête est autorisée, soumise à confirmation ou refusée, avec les règles qui motivent la décision.

DémarrerLire les guides
Dans votre projet
shield init
shield status
shield doctor
Règles du projet

Commencez par des règles que vous pouvez vérifier.

shield init installe un ensemble de règles de base signé et connecte vos agents. Choisissez le profil Loose, Recommended ou Strict, puis vérifiez et confirmez les modifications.

Ajoutez des ensembles d’autorisations pour vos outils ou définissez des règles YAML ou JSON précises pour les commandes, les arguments, les chemins et les adresses web. Les agents peuvent proposer des règles, et vous devez confirmer les modifications.

Ensembles d’autorisations
shield pack search node
shield pack add node --profile strict
shield pack update
Installation

Compilez un outil en ligne de commande Rust depuis les sources.

Shield n’est pas encore disponible dans les gestionnaires de paquets. Installez Rust, clonez le dépôt et compilez l’outil. La version de la chaîne d’outils est définie dans le dépôt.

Sur macOS et Linux, la commande installe shield dans ~/.local/bin. Ajoutez ce dossier à votre PATH. Sous Windows, la version compilée à partir du code source prend en charge l’inscription des projets et les hooks de Claude Code et de Codex. Installation sous Windows

Shield vérifie les requêtes soumises. Il ne remplace pas le bac à sable de l’agent et ne s’applique pas si l’hôte ignore ses hooks. Qu’est-ce que Shield ?

Terminal
git clone https://github.com/canonic2/canonic.git
cd canonic/packages/shield
cargo xtask install
