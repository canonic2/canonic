Rule reference

This reference covers document fields, rule fields, and selectors. For your first rule, start with the rule-writing guide.

You need to look up… Section

A rule’s decision, conditions, or unmet branch Rule fields

Working directories and affected paths Locations and domains

Document format

Shield accepts UTF-8 JSON or a single YAML document using schema_version: 1. Keys must be strings. Unknown fields, duplicate keys, unsupported capabilities, and YAML anchors and aliases are rejected. Omit optional source fields instead of setting them to null; exact-request payloads can retain their supplied null values. Documents support no environment interpolation, command substitution, or includes.

Field Project custom rules Permission pack
schema_version Required integer 1. Required integer 1.
kind Required custom. Required pack.
capabilities Required list of exactly the capabilities used. Same.
rules Required array with unique rule IDs; may be empty. Same.
directory_options Optional directory option declarations. Same.
id, version Not accepted. Required publisher/name and semantic release version.
description, license, maintainers Not accepted. Required nonempty description, license text, and nonempty maintainer list.
engines Not accepted. Required object containing only shield, with its supported semantic-version requirement.
dependencies Not accepted. Optional dependency declarations; see packs.
variables, preconditions Not accepted. Optional declarations; see pack variables.
invocations, command_sets Not accepted. Optional shared bodies; see rule reuse.

Project configuration selects the rule file. Documents cannot select a project, operator identity, or cache root. A saved edit applies to the next request.

Rule fields

Field Meaning
id Required stable identifier, unique within the document: 1–128 ASCII bytes, beginning with a letter or digit, then letters, digits, ., _, :, or -.
decision Required allow, ask, or deny. Pack rules may instead map all three profiles: loose, recommended, strict.
conditions Required object with a domain and the predicates that make this rule apply.
requirements Optional nonempty object of additional predicates, all of which must be verified for the successful decision.
on_unmet Required exactly when requirements is present; an ask or deny decision with optional message and alternatives.
reason Optional nonempty explanation, at most 4,096 UTF-8 bytes.
guidance Optional successful-branch message and/or alternatives.
expires_at Optional quoted UTC timestamp for custom rules; an expired rule contributes nothing.
fallback Pack-only true; lets this rule yield to regular decisions from other packs.
invocation, command_set Pack-only references to shared definitions; command_set requires invocation.
when Pack-only activation tests on declared variables.
agents Agent-specific outputs; see Codex prefix rules.

Guidance messages are at most 512 UTF-8 bytes. Alternatives contain one to three nonempty strings, each at most 256 bytes. They suggest new requests to evaluate; they do not authorize or rewrite the current request.

Rule order does not determine precedence. See how rules combine.

Text selectors

Shape Matches
verify or {exact: verify} The complete literal field.
{prefix: verify} Text starting with verify.
{one_of: [verify, report]} One of the listed literal values.
{glob: '*.txt'} A glob against one field; * does not cross a path separator.
`{regex: ’get describe’}`
{not: {one_of: [prod, admin]}} A present value the inner selector does not match.

Selectors do not expand an argument into additional arguments. The shell command acme-check "two words" has one argument containing a space, not two arguments. Glob and regex selectors require their respective capabilities; not requires negated-selectors-v1. A not selector never matches a missing value, so pair it with require_all when the option must be present.

Argument selectors

The arguments condition describes the arguments after the executable.

kind Fields Use
any No additional fields. Accept any argument list.
exact values: literal string array. Match the complete argument list, including an empty list.
prefix values: selector array; optional leading grammar. Match the start and leave the suffix unrestricted. Leading options require prefix-leading-v1; leading.interleaved: true also accepts them between prefix words and requires interleaved-leading-v1.
sequence prefix: selector array; rest: none, any, or each. Match initial tokens and constrain the rest.
options prefix, flags, values, operands; optional parsing controls. Accept a declared operation and reviewed options.
risk_tokens prefix, any_of. Detect restrictions conservatively; cannot grant Allow.

For a sequence, rest: {kind: none} rejects remaining arguments; rest: {kind: any} accepts them. Use rest: {kind: each, match: SELECTOR, min: N, max: N} to constrain each remaining argument. Counts default to 0–256.

An options grammar distinguishes flags from options that consume a value:

kind: options
prefix: [verify]
flags: [--verbose]
values: [--format]
operands: false

This fragment accepts verify, verify --verbose, and verify --format json. It rejects verify --format and verify report.txt. It does not restrict the format value to JSON; use {name: --format, match: json} in values for that.

Declared options are optional unless required. Unknown options fail matching. Use require_all, require_any, and forbid to check declared option names. leading: {flags: [...], values: [...]} declares global options before the operation. operands is false, true, or {match: SELECTOR, min: N, max: N}. The -- separator ends option parsing; subsequent tokens are operands.

Some tools read global options anywhere, among options a rule cannot list. unknown_options: skip passes over undeclared options so a grammar can still check the declared ones; it needs operands: true. long_abbreviations: true accepts any unique prefix of a declared long option, as argparse-based tools do, so declare the tool’s complete global option set when you use it. This requirement accepts any AWS command that names the acme-ro profile, written in full or abbreviated, anywhere in the command:

kind: options
prefix: []
flags: [--debug, --no-paginate, --no-verify-ssl, --no-sign-request]
values: [{name: --profile, match: acme-ro}, --region, --output, --query, --endpoint-url]
operands: true
unknown_options: skip
long_abbreviations: true
require_all: [--profile]

It allows aws logs tail g --since 1h --prof acme-ro and refuses aws s3 ls --profile acme-admin. The settings require unknown-options-v1 and option-abbreviations-v1. Skipping says nothing about what the skipped options do, so allowances for specific operations keep their declared grammars.

With abbreviations disabled, skip mode refuses prefixes of declared long names such as --prof or --prof=value for --profile. Unrelated undeclared options are still skipped.

Skip mode also refuses short-option tokens containing a declared option behind an undeclared letter. For example, a requirement on -X refuses -kXPOST when -k is undeclared, since skipping it could hide an override of -X. Declare -k as a flag to parse that cluster normally. A declared valued option still consumes its attached suffix as a value.

For a worked example of forwarding --watch to a project script, see argument matching. Use requirements with an on_unmet branch when an option violation should contribute a rejection instead of making the entire rule miss.

Locations and domains

An argv rule can match the executable, arguments, and cwd. File rules match typed file operations. Shell rules match shell input. Web rules match searches, fetches and supported loopback HTTP requests. MCP rules match MCP requests. exact_request binds the complete normalized input and context rather than just the command arguments. The guided CLI defaults to that exact-request form; explicitly choosing argv broadens the vendor/environment binding.

Path predicates use exact, within, or outside. References use project, absolute, read, or write roots. Read/write roots require access-paths-v1; their configured directories are described in additional access paths.

Use a cwd predicate to constrain where a command starts. Use target predicates to constrain its observed file effects. Use argument_paths to check explicit path operands without claiming a complete model of the tool’s effects. See path restrictions and supported operations and web rules.

MCP rules can check explicit path arguments with field_paths, for example field_paths: {/project: {path: {within: {root: write}}, absolute: true}}. This requires field-paths-v1, location-v1 and access-paths-v1. Paths use filesystem observations, including symlink resolution; unavailable evidence does not establish permission. absolute: true requires an absolute path. Without relative_to, relative paths fail the predicate. Use absolute paths when the server’s path base is unknown, relative_to: cwd only when it shares the request context’s working folder, or relative_to: project when a verified launcher starts the server at the enrolled project root.

To check paths inside an array, point the field_paths key at the array and set each to the JSON Pointer for a path within each item, such as /path. An empty each checks each item directly. Missing path members are skipped. A malformed array, a present non-string path, or more than 128 array items across one predicate fails the check. This also requires field-path-arrays-v1.

Local HTTP requests

Use action request to review a shell HTTP operation by method and endpoint. Declare local-http-requests-v1 and specify both method and url. The following rule permits a POST to one development endpoint on the loopback interface.

id: reload-local-service
decision: allow
conditions:
  domain: web
  action: request
  method: POST
  url:
    schemes: [http]
    hosts: [127.0.0.1]
    ports: [8080]
    path: {exact: /-/reload}
  request_fields:
    /body: {exact: false}

The command can use curl --request POST http://127.0.0.1:8080/-/reload. Curl can also pin a localhost or .localhost hostname to loopback. Put -q first, pass --noproxy '*', and use a matching pin such as --resolve api.localhost:8080:127.0.0.1. The rule matches the URL’s hostname and port. Wget uses the literal 127.0.0.1 address. Use literal paths with percent escapes and dot segments omitted.

For an endpoint you trust through ordinary hostname resolution, declare local-http-hostname-resolution-v1 and add /hostname_resolution: {exact: system}. This requires one scheme, one exact localhost or .localhost hostname, one port and one exact path in conditions.url. It covers host curl commands without a --resolve pin. Shield checks command options, client configuration and proxy settings. Use a pinned request when the connection must stay on IPv4 loopback regardless of hostname resolution.

For example, allow one reviewed read-only MCP tool on a workspace endpoint:

id: query-workspace-metrics
decision: allow
conditions:
  domain: web
  action: request
  method: POST
  url:
    schemes: [http]
    hosts: [metrics.workspace.localhost]
    ports: [8080]
    path: {exact: /mcp}
  request_fields:
    /hostname_resolution: {exact: system}
    /rpc_method: {exact: tools/call}
    /rpc_tool: {exact: query_metrics}

Put related endpoint rules into one policy_propose review. Select handshake operations by /rpc_method, and tool calls by both /rpc_method and /rpc_tool. Review the effect of each tool at the endpoint before allowing it.

request_fields uses JSON Pointer selectors. /client is shell and /redirects is none. /body and /basic_auth are booleans. /headers is an array of lowercased header names. For a recognized JSON-RPC body, /rpc_method contains the method and /rpc_tool contains the tool name for tools/call. Header values and credentials are absent from these fields. A fetch rule covers its own separate action.

Isolated Docker validators

The docker_isolated_bind requirement checks a docker --context NAME run invocation. Declare docker-isolated-bind-v1, argument-rules-v1, requirements-v1 and location-v1 alongside structured-rules-v1.

id: validate-local-config
decision: allow
conditions:
  domain: argv
  executable: docker
  arguments:
    kind: options
    prefix: [--context, dev, run]
    flags: [--rm]
    values: [--pull, --network, --mount, --env]
    require_all: [--rm, --pull, --network, --mount]
    parse: stop_at_operand
    operands:
      match: {one_of: ["acme/validator:1", check, /etc/acme/config.yml]}
      min: 3
      max: 3
  cwd: {exact: {root: project}}
requirements:
  docker_isolated_bind:
    context: dev
    image: "acme/validator:1"
    command: [check, /etc/acme/config.yml]
    source: {exact: {root: project, path: config.yml}}
    target: /etc/acme/config.yml
    environment: [MODE=validate]
on_unmet:
  decision: ask

context selects the operator’s Docker context. image and command match the literal image reference and its entrypoint arguments. Use a digest if the image identity must be immutable. source selects an existing regular project file and target names its absolute container path. The optional environment lists permitted literal NAME=value assignments for --env.

The run requires --rm, --pull never, --network none and a single --mount type=bind,source=…,target=…,readonly. The source check covers the CLI host file. Shield still asks about the image entrypoint because the Docker daemon resolves the mounted file on its own host. For the rule above, the command is:

docker --context dev run --rm --pull never --network none \
  --mount type=bind,source=./config.yml,target=/etc/acme/config.yml,readonly \
  --env MODE=validate acme/validator:1 check /etc/acme/config.yml

GraphQL requests

An argv predicate graphql: {carrier: gh-api, operation: query} verifies a supported inline gh api graphql query. It requires graphql-v1 and the ordinary argument/executable selectors. Parsing does not itself allow the request: the rule’s decision, requirements, other policy and host restrictions still apply. Custom rules and packs can declare this implemented capability and supply their own reviewed selection models. Engine support does not add query permissions to installed packs; inspect their actual rules before relying on an allowance.

The carrier accepts inline -f strings and scalar -F fields, one selected query operation, scalar defaults, aliases and fragments. Optional operationName selects a named operation. --paginate requires a nullable $endCursor: String used only in cursor arguments. Supported output flags are --silent, --include/-i and paginated --slurp; explicit method/hostname are limited to POST and github.com. Known conflicting host context fails verification.

File/stdin input, typed placeholders, object-valued variables, list values, mutations, custom headers, alternate endpoints/hosts, --jq, templates and unknown syntax do not satisfy a query predicate; mutation predicates admit reviewed mutations and their input objects. A query classification without selection accepts structurally valid object argument literals and asserts no repository scope. Source names and related metadata checks do not attest the actual network destination or immutable repository identity.

An optional selection has root and states. Each state declares accepted fragment types and a fields map. A field has either leaf: true or select: STATE, plus optional arguments. Query-root fields can instead use subtree: true with graphql-subtree-v1: their own arguments are checked, but all descendant fields, arguments and fragment types are unrestricted. A subtree requires a child selection and can appear only in the root state with exactly types: [Query]. It permits related objects outside the named repository. Document, variable, directive and resource checks still apply; descendant object argument literals are accepted within the existing input-depth bounds, while list inputs and object-valued variables remain unsupported. Each argument declares match as {text: SELECTOR}, {exact: SCALAR} or {scalar: string|integer|number|boolean|enum}, with optional required, nullable and cursor booleans defaulting to false. Every modeled field and argument must be declared; aliases do not replace actual field names. Missing required scope values and unknown modeled traversals fail. A cursor declaration must be optional, nullable and {scalar: string}. Pack text selectors can use prepared variable projections. Source models contain no executable code or live schema queries. Invalid models make the policy files invalid; exhausted analysis limits block rather than falling back to an allowance. Rules using this predicate cannot export agents.codex.prefixes: a command prefix cannot represent query or selection constraints.

For example, this requirement fragment admits name metadata only from the named repository; put it inside an argv rule’s requirements and supply on_unmet:

graphql:
  carrier: gh-api
  operation: query
  selection:
    root: query
    states:
      query:
        types: [Query]
        fields:
          repository:
            arguments:
              owner: {required: true, match: {text: acme}}
              name: {required: true, match: {text: web}}
            select: repository
      repository:
        types: [Repository]
        fields:
          nameWithOwner: {leaf: true}

The query { repository(owner:"acme", name:"web") { nameWithOwner } } satisfies this model; adding parent { nameWithOwner } does not. Use a Deny unmet branch when failure must block rather than follow Ask fallback. See conditions and requirements.

For a root-only boundary, replace select: repository with subtree: true and omit the repository state. Every root must still be declared and match its arguments, including roots inside fragments and conditional selections. Nested reads such as parent { nameWithOwner } then pass without a field inventory.

GraphQL mutations

graphql: {carrier: gh-api, operation: mutation, root_fields: [...], selection: ...} classifies a selected mutation by the root fields it calls. It requires graphql-mutations-v1 in addition to graphql-v1. It checks the request’s shape, not its target: GitHub mutations name objects by opaque IDs, which Shield does not look up, so a mutation predicate never confirms which repository it changes.

  • selection is required, and its root state’s types must be exactly [Mutation]. List every mutation you review in that one model, with its arguments and the payload fields it may return. A request calling any other root field fails the predicate.
  • root_fields names one class of those mutations. The predicate is met when the request calls at least one of them. Give each class its own rule with the same model: a request calling fields from several classes meets each of their rules, and the strictest decision applies. Fields under fragments or @skip/@include count; aliases do not replace actual names.
  • An input object argument uses match: {object: {FIELD: ARGUMENT}}, whose fields follow the argument rules above and may nest up to four levels. Every input field must be declared, and a repeated key fails. Object matchers are accepted only in mutation models. Lists, object-typed variables and --paginate do not satisfy a mutation predicate.

For example, this condition matches requests that resolve or unresolve review threads and return only the thread’s ID and state:

graphql:
  carrier: gh-api
  operation: mutation
  root_fields: [resolveReviewThread, unresolveReviewThread]
  selection:
    root: mutation
    states:
      mutation:
        types: [Mutation]
        fields:
          resolveReviewThread:
            arguments:
              input:
                required: true
                match:
                  object:
                    threadId: {required: true, match: {scalar: string}}
            select: payload
          unresolveReviewThread:
            arguments:
              input:
                required: true
                match:
                  object:
                    threadId: {required: true, match: {scalar: string}}
            select: payload
      payload:
        types: [ResolveReviewThreadPayload, UnresolveReviewThreadPayload]
        fields:
          thread: {select: thread}
      thread:
        types: [PullRequestReviewThread]
        fields:
          id: {leaf: true}
          isResolved: {leaf: true}

mutation { resolveReviewThread(input:{threadId:"T1"}) { thread { id isResolved } } } meets it; adding pullRequest { title } under thread does not.

Capabilities

Typed JSON field maps (fields, request_fields and MCP connection) accept {not: {exact: VALUE}} to match a present value unequal to VALUE. Missing fields never match this predicate; a present null remains distinct from absence. For example, /env: {not: {exact: {}}} detects supplied non-empty environment maps without matching an omitted or empty map. This requires both field-negation-v1 and negated-selectors-v1. Nested field negation and negated text predicates are not accepted; use a text selector’s own not for the latter.

Declare exactly the capabilities used anywhere in the document, once each.

Capability Required for
structured-rules-v1 Every document.
argument-rules-v1 Argument selectors in argv rules.
argument-paths-v1 Explicit argument-path checks.
docker-isolated-bind-v1 A docker_isolated_bind requirement checks a Docker image invocation and its single read-only project file bind.
local-http-requests-v1 The web request action selects a method and URL for a supported loopback HTTP request.
local-http-hostname-resolution-v1 A web request rule explicitly accepts hostname resolution for one local curl endpoint.
graphql-v1 Parsed inline GitHub GraphQL query predicates and finite selection models.
graphql-mutations-v1 GraphQL predicates with operation: mutation.
graphql-subtree-v1 Query-root fields with unrestricted descendant selections.
field-paths-v1 Explicit path checks on MCP JSON fields.
field-path-arrays-v1 Path checks on all items of a bounded MCP JSON array.
glob-v1, regex-v1 Their respective text selectors.
location-v1 Path references/predicates, cwd, file domains, or targets.
access-paths-v1 read or write root unions.
requirements-v1 Requirements and their unmet branches.
possible-effects-v1 Possible-effect predicates.
fallback-rules-v1 Pack fallback rules.
dependencies-v1 A dependencies array, including an empty one.
invocation-groups-v1, command-sets-v1 References to their respective shared pack definitions.
prefix-leading-v1 Leading options on a prefix argument selector.
interleaved-leading-v1 interleaved: true in a leading grammar, on prefix or options selectors.
variables-v1 Pack variables, variable selectors, or activation tests.
variable-parts-v1 Literal parts of string/choice variables selected with split.
variable-prefixes-v1 A prefix text selector joined from literal text and string/choice variables.
variable-list-branches-v1 A precondition requires_any branch that splits a list variable or uses it as a prefix part, repeated once per item.
preconditions-v1 Pack preconditions.
directory-options-v1 Directory option declarations.
templates-v1 Variable templates in pack explanation text.
agent-outputs-v1 Agent-specific rule outputs.
mcp-integrations-v1 Pack MCP integration definitions and defaults.
mcp-connection-facts-v1 Typed connection predicates over reviewed MCP facts.
mcp-effective-fields-v1 Pack mappings from request fields and reviewed defaults to effective facts.
mcp-command-fields-v1 Declared MCP fields evaluated as literal fixed-executable commands.
field-negation-v1 Typed JSON field predicates using {not: {exact: VALUE}}.
unknown-options-v1 unknown_options: skip in an options grammar.
option-abbreviations-v1 long_abbreviations: true in an option phase.
negated-selectors-v1 not text selectors.

An argv rule with an argument selector needs structured-rules-v1 and argument-rules-v1. Add location-v1 for a cwd predicate and requirements-v1 for requirements and their unmet branch. Plain string selectors need neither regex-v1 nor glob-v1.

Use pack validation to check documents without activating them. Validation checks syntax and policy structure; review the tool’s behavior before granting permission.
